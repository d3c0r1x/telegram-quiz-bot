# Telegram Quiz Bot

Викторина в Telegram: 10 вопросов, 4 варианта ответа, кнопки, счёт, лидерборд. Вопросы — из бесплатного публичного API **OpenTDB**, а если он недоступен — из встроенного оффлайн-пула.

## Команды

- `/quiz` — выбрать сложность и начать игру
- `/leaderboard` — топ игроков (с пагинацией, по 5 строк)
- `/stats` — моя статистика: сколько игр, лучший счёт, точность в %, последние 5 игр

## Как играется

```
/quiz
→ «Выберите сложность:» (🎲 любая / 🟢 лёгкая / 🟡 средняя / 🔴 сложная)
→ Вопрос 1/10 с 4 вариантами
→ жмёшь вариант → «✅ Верно!» / «❌ Ошибка. Правильный ответ: ...»
→ в конце: «🏆 Игра окончена! Ваш результат: 9/10»
```

## OpenTDB: что оказалось неожиданным

- API бесплатный и без ключа (документация: https://opentdb.com/api_config.php), формат — `GET ...?amount=10&type=multiple` → `response_code` и массив `results`.
- **Вопросы приходят с HTML-сущностями** (`&quot;`, `&#039;`) — снимаю через `html.unescape` из stdlib.
- При перегрузке API возвращает `response_code=1` — тогда бот откатывается на встроенный русскоязычный пул вопросов, чтобы игра всё равно состоялась.
- В демо-режиме (`QUIZ_DEMO_MODE=1`, по умолчанию) сеть не нужна вовсе.

## Про защиту от «двойного ответа»

Классическая проблема: пользователь нажимает кнопку из **прошлой** игры — бот засчитывает ответ в новую. Решение: в `callback_data` зашивается nonce текущей игры, устаревшие кнопки отклоняются с alert «кнопка устарела». Есть и очистка брошенных игр (сессии старше 30 минут вычищаются, чтобы память не текла).

## Интеграционные тесты — это было весело

Обычные unit-тесты не проверяют настоящий путь обработки. Поэтому я написал `tests/test_live_flow.py`: **настоящий Dispatcher** бота кормится настоящими Telegram-апдейтами (`/start → /quiz → выбор сложности → 10 ответов → /leaderboard → /stats`), а все исходящие вызовы Bot API перехватываются своей `CapturingSession` — сеть не нужна, тест детерминирован. Отдельно проверены неверный ответ (должен показать правильный) и устаревшая кнопка (должна быть отклонена).

## Запуск

```bash
python -m venv .venv
pip install -r requirements.txt
export QUIZ_BOT_TOKEN=123456:ABC...   # токен от @BotFather
export QUIZ_DEMO_MODE=1               # 0 — реальный OpenTDB
python bot.py
```

На Windows — `run_bot5.cmd` (токен из корневого `.env`).

## Из чего состоит

```
bot.py          — команды, игровой цикл, кнопки, nonce-защита
quiz_api.py     — запросы к OpenTDB, оффлайн-пул, построение URL со сложностью
db.py           — SQLite: статистика, лидерборд, журнал игр
middlewares.py  — троттлинг и логирование
config.py       — настройки из переменных окружения
tests/          — 10 тестов (7 unit + 3 интеграционных)
```
